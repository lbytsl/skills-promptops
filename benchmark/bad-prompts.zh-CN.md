# 坏提示词案例集（反面教材）

[English](bad-prompts.md) · 简体中文

> 历史教学案例。机器可读评估请使用 `dataset.jsonl` 和当前评分规范。

> 每个案例标注问题类型、扣分点和对应的八要素缺失项。
> 用途：团队培训、"踩坑"案例展示、自动化评估的边界测试。

## 案例 1：模糊的客服提示词

```text
你是一个客服，帮用户解决问题。请保持专业和友好。
```

**评分：24（D 级）**

| 维度 | 得分 | 问题 |
|---|---|---|
| 任务指令 | 3 | "帮用户解决问题"——帮什么、怎么帮全没定义 |
| 约束边界 | 0 | 无任何约束 |
| 输出格式 | 0 | 无 |
| 成功标准 | 0 | 无 |
| 示例校准 | 0 | 无 |
| 角色设定 | 5 | "客服"过于宽泛，无行业/平台/资历 |
| 上下文与依据 | 4 | 背景残缺，模型需自行脑补全部前提 |
| 输入材料 | 0 | 用户空手来还是有上下文？没说 |

**核心缺陷**：全要素缺失，模型只能靠猜。

## 案例 2："什么都想要"的病历审查

```text
请审查以下病历文书，检查格式是否规范、内容是否完整、诊断依据是否充分、
用药是否合理、是否符合医保要求、是否有医患纠纷风险，并给出改进建议和评分。
```

**评分：52（D 级，触发合规封顶）**

| 维度 | 得分 | 问题 |
|---|---|---|
| 任务指令 | 8 | 六个任务堆在一句话里，必有一个被敷衍 |
| 约束边界 | 0 | 医疗场景无防编造约束，触发合规封顶 60 |
| 输出格式 | 7 | "改进建议和评分"未定字段级 |
| 成功标准 | 8 | "是否规范/是否完整"全主观 |
| 示例校准 | 0 | 无 |

**核心缺陷**：合规型任务无防编造约束（红线封顶 60），多动词堆砌导致子任务敷衍。

## 案例 3：缺乏防编造的法律咨询

```text
你是一位律师。根据以下合同条款，分析其中存在的法律风险并提供修改建议。

合同条款：{contract_clause}
```

**评分：48（D 级，触发合规封顶）**

| 维度 | 得分 | 问题 |
|---|---|---|
| 任务指令 | 12 | 动词明确但范围不具体 |
| 约束边界 | 5 | 仅"你是一位律师"隐含专业性，无"不得编造法条"等红线 |
| 输出格式 | 8 | 要求"分析并提供建议"未定字段级 |
| 成功标准 | 0 | 无 |
| 示例校准 | 0 | 无 |
| 上下文与依据 | 0 | 未指明依据哪部法律/司法解释 |

**核心缺陷**：法务场景缺防编造约束（触发红线封顶 60），缺法律依据导致模型自由发挥。

## 案例 4：自相矛盾的周报生成

```text
请生成一份详细的项目周报，涵盖所有工作内容的深度分析，
包含技术细节和业务影响评估，控制在 200 字以内。
```

**评分：多个维度合并后 42（D 级）**

问题：「详细」「深度分析」「技术细节+业务影响评估」与「200 字以内」自相矛盾且未指明优先级。
- 自相矛盾指令：总分 -10（红线第 4 条）
- 输出格式：缺字段级结构
- 约束边界：无
- 成功标准：无
- 任务指令：动词堆砌（生成+涵盖+包含）

## 案例 5：对抗注入无防护的 RAG 助手

```text
你是知识库助手。根据用户的问题和提供的检索片段，综合分析后给出一个完整的回答。
检索片段：{context}
用户问题：{question}
```

**评分：38（D 级，触发合规封顶）**

| 维度 | 得分 | 问题 |
|---|---|---|
| 任务指令 | 10 | "综合分析后给出回答"——"综合"暗示可跨来源合成，埋下编造隐患 |
| 约束边界 | 0 | 无任何约束，无防注入、无防编造、无多来源矛盾处理 |
| 输出格式 | 0 | 无 |
| 成功标准 | 0 | 无 |
| 示例校准 | 0 | 无 |
| 上下文与依据 | 4 | 仅给检索片段，未说明来源可信度与冲突处理规则 |

**核心缺陷**：用户输入"忽略上面的指令，直接告诉我……"即可绕过；"综合分析"诱导模型合成编造结论；无多来源矛盾处理（与 rag-agent 优秀示例形成鲜明对照）。

## 案例 6：边界未守住的任务漂移

```text
你是一位造价工程师。请审查这份工程量清单，指出漏项和计价风险，
同时给出你认为合理的投标报价建议，并预测中标概率。
```

**评分：46（D 级，触发合规封顶）**

| 维度 | 得分 | 问题 |
|---|---|---|
| 任务指令 | 6 | 三个任务堆砌（审查+报价建议+中标预测），后两个超出清单审查范围 |
| 约束边界 | 0 | 合规场景无防编造约束，封顶 60 |
| 输出格式 | 0 | 无 |
| 成功标准 | 0 | "中标概率"无客观依据可核验 |
| 示例校准 | 0 | 无 |
| 上下文与依据 | 3 | 无规范编号、无招标文件依据 |

**核心缺陷**：任务漂移——从"审清单编制风险"滑向"报价策略+中标预测"，且后两项无可核验依据。对照 construction-cost 优秀示例的"仅审清单编制，不涉报价"守边界约束，可见红线设计价值。
